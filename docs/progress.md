## M1 可玩原型 ✅ (2026-09-21)

**做了什么**
- Vite + three.js 脚手架；程序化城市（8×8 街区、Canvas 路网地面纹理、低模塔楼 + 霓虹描边、公园/工地、路口霓虹桩 InstancedMesh）
- 机器人骑手驾驶：W/S 加减速、A/D 转向（低速转向权重衰减）、Shift 加速、建筑 AABB 碰撞推出+减速、压弯倾斜
- 订单循环：报价池自动生成 → Enter 接单 → 取餐点 E 取餐 → 送达点 E 交付 → 计时 + 收入（准时加成/超时折扣）
- HUD：时间/收入/订单倒计时/报价列表/交互提示/时速；WebAudio 合成音效（引擎、接单、取餐、到账、碰撞）
- 修复：订单报酬计算优先级 bug（reward 被除以 10）
- `window.__game` 调试句柄 + Playwright e2e（完整 chromium 二进制无头模式）

**怎么验证的**
- `npm run build` 通过；`node test/e2e.mjs m1` 10 项全 PASS：冷启动、W 加速且位移沿车头方向(fwdDot=1.00)、A 左转 Δheading=1.98、接单→取餐→送达全流程、收入 ¥0→¥6.8、时钟推进、无控制台报错
- 截图人工检查：城市霓虹夜景、HUD、取餐标记、到账 toast 均正常渲染

**截图**：docs/shots/m1-01-city.png、m1-02-pickup-marker.png、m1-03-delivered.png

**已知问题**
- 画面整体偏暗（M5 灯光打磨时处理）
- 偶发 0.0km 超短单（取送点太近；M3 加最小距离约束）

## M2 路线系统 ✅ (2026-09-21)

**做了什么**
- `RoadNetwork`：9×9 路口节点图 + A* 寻路 + 边状态（封路/减速，供 M3 事件用）+ 路径长/ETA 估算
- 送前暂停规划（PLAN 状态）：接单后世界冻结，大地图显示完整路线、每段距离与 ETA、预计总耗时、不可达告警；Enter 出发，N 切换自动导航
- 多停留点规划：贪心最近邻 + 先取后送约束，多单自动排访问顺序
- 自动导航：3D 霓虹路线带（CurvePath+Tube）、骑手头顶导航箭头、偏离 18m 自动重规划
- 小地图（Canvas 2D）：路网、封路/拥堵着色、路线、编号停靠点、骑手朝向三角
- 主标记 + 后续停靠点幽灵标记

**怎么验证的**
- `node test/e2e.mjs m2` 17 项全 PASS：接单进入 PLAN、ETA>0 且 2 停靠点、Enter 确认回 RIDE、路线带显示/随开关切换、取餐→送达收入 ¥0→¥6.8、两单规划 4 停靠点全可达、时钟推进、无报错
- 截图人工检查：规划界面排版与路线、小地图、3D 路线带均正常
