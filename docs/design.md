# 《送外卖模拟器》设计文档（可执行方案）

代号：**NEON RIDER / 霓虹骑手**。赛博朋克城市里的机器人骑手，低多边形 + 霓虹。

## 0. 技术底座
- three.js + Vite + 原生 ES Modules (JS)。`npm run build` 产出 `dist/` 静态站点。
- 美术全部程序化：低多边形几何体 + 自发光霓虹材质（MeshStandardMaterial emissive / MeshBasicMaterial）。
- 音效：WebAudio 合成（引擎嗡鸣、接单提示、到账、碰撞、UI 音）。
- 数据驱动：数值集中在 `src/config/*.js`（balance / map / orders / events / knowledge），改数值不改逻辑。

## 1. 游戏流程（状态机）
```
TITLE → PM_INTRO(产品经理俯视角小游戏) → LAYOFF(被裁转场) 
  → SHIFT_SELECT(自选上班时段) → WORKDAY(8小时循环) → SETTLEMENT(日结算) → TITLE
```
WORKDAY 内部循环：`接单(OFFER) → 送前暂停规划(PLAN) → 骑行配送(RIDE) → 单结算(即时) → …` → 8小时到点 → SETTLEMENT。

## 2. 产品经理开场（约2-3分钟，俯视角）
- 俯视角看城市与若干 AI 骑手在跑单。
- 玩家扮演平台产品经理，每一轮收到"算法优化提案"：把某类订单的时限再压缩 N 分钟。
- 操作：在面板上点选压缩方案（3轮决策）。每次压缩都看到骑手更赶、事故/超时增多，但"预计收入曲线"上升 → 为后面被压缩时限埋下因果。
- 结束触发剧情：公司业绩 OKR 未达标，产品经理自己被"算法优化"裁掉 → 转场。

## 3. 骑手模式（核心）
- 视角：**俯视跟随为主**（斜45°跟随镜头）；取餐/送餐到店门口时短暂平滑推近到近肩视角增加沉浸感，不做生硬切换。开场转场从第一人称走入站点，之后以俯视为主。
- 操作：WASD/方向键骑行，Shift 加速（耗电/发热），空格 刹车/漂移，E 交互（取餐/送达/上下人行道），Esc 暂停。
- 单局时长：8 游戏小时 ≈ 16 分钟现实（1h = 2min）。

### 核心循环
1. **接单**：订单以推送卡片出现（显示商家→顾客、距离、时限、报酬），可接可拒；高峰期可同时多单。
2. **送前暂停规划（PLAN）**：接单后进入暂停规划界面：大地图显示取餐点/送达点、预计总耗时（ETA）、可调整配送顺序，可开启**自动导航**（随后骑行时有箭头/路线指引）。
3. **骑行配送**：沿路网骑行。取餐点按 E 取餐，送达点按 E 交付。每单有倒计时。
4. **结算**：每单即时结算（基础运费+准时奖励+小费-超时扣款），日终总结算。

## 4. 城市与路网
- 网格城市：约 8×8 街区，主干道/次干道两级路网，路宽不同（影响速度）。
- 数据：`config/map.js` 定义网格尺寸、街区类型（商业/住宅/工地/公园）、POI（商家/顾客/站点）、施工区、捷径坡道位置。
- 路网图：节点=路口，边=路段。A* 寻路用于 ETA 和自动导航。
- POI 程序化生成：商家（餐厅霓虹招牌）、住宅楼、工地（含可跳坡道）、围墙（可跳抄近路）。
- 人行道：堵车路段可骑行上人行道（速度低于马路但绕过堵车）。

## 5. 温水煮青蛙难度
- 系统跟踪玩家最近 N 单的"实际用时/标准用时"比率。
- 表现越好，新订单时限系数逐步收紧（下限保护，不会突变）；表现差则略放松。
- 全部参数在 `config/balance.js`。

## 6. 随机事件（≥8种，好坏参半）
定义在 `config/events.js`，每事件：触发条件、权重、效果钩子。
1. 道路施工封路（某路段临时不可通行，需重新规划）
2. 交警查车（机器人年检：被拦停 10 秒，若"手续齐"知识已解锁则快速放行）
3. 订单转让（高风险高回报：绕路接别的骑手转让的单，报酬加成但时限紧）
4. 顺路加单（好事：当前路线附近新单，接了顺路）
5. 好心顾客小费（送达后随机小费）
6. 暴雨/霓虹雾（能见度下降、路面打滑 → 操控漂移增大；报酬补贴）
7. 堵车（主干道车流激增速度下降，可上人行道绕行）
8. 电池告警（需要到充电桩闪充 15 秒，否则限速）
9. 商家出餐慢（取餐等待，可与"提前取餐"知识联动）
10. 迷路无人机指路（好事：短时间内显示最优路线）

## 7. 知识锁（≥6条）
`config/knowledge.js`。通过日结算"经验值"或特定行为解锁，解锁后被动生效或在规划界面可用：
1. 提前取餐：到店前可提前预约出餐，减少等餐时间。
2. 合并顺路单：规划界面允许一键合并方向一致的两单，ETA 智能合并。
3. 高峰避雷：地图上显示历史拥堵点，高峰期自动提示绕行。
4. 抄近路大师：标记所有可跳围墙/坡道捷径，跳跃速度惩罚降低。
5. 续航管理：电池消耗降低，充电更快。
6. 交警熟人：查车事件快速放行。
7. 顾客心理学：小费概率提升。

## 8. 时间与昼夜
- 8:00–24:00 之间自选 8 小时时段（SHIFT_SELECT 提供 3 个预设：早班/午晚高峰班/夜班）。
- 饭点高峰（11-13、18-20）：单量多、报酬高、拥堵高；平峰相反。
- 光照：太阳方向/颜色/环境光随时间插值；夜晚霓虹点亮、天空盒颜色渐变（雾 + 背景色 + 程序化星空/城市光晕）。

## 9. UI/HUD
- HUD：当前时间、当日收入、电量、持有订单列表（每单倒计时）、速度表、迷你地图。
- 迷你地图：Canvas 2D 绘制路网 + 骑手位置 + 订单标记 + 事件区。
- 结算画面：收入明细、准时率、里程、事件回顾列表、解锁的知识。

## 10. 验收纪律
- 每里程碑用 Playwright 无头 Chromium 跑 `test/e2e.mjs`：加载→截图→模拟完整接单到送达→断言收入变化。
- 游戏暴露 `window.__game` 调试句柄（场景状态、订单、收入、时间快进 API）供测试驱动。
- 验收记录写入 `docs/progress.md`，截图存 `docs/shots/`。

## 11. 性能
- 建筑/路灯等静态物体合并几何或 InstancedMesh；粒子用 Points；目标桌面 60fps。
